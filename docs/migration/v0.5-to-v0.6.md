# anvil v0.5 → v0.6 migration guide

> **TL;DR.** Upgrade is a drop-in for single-tenant docker deployments —
> all v0.5.x behavior is preserved bit-identically when operators don't
> configure any of the new knobs. Each v0.6 feature is either
> default-on-but-no-op-without-config, or default-off-pending-opt-in.

## 1. Drop-in upgrade (single-tenant docker)

If you're running anvil v0.5.x with docker agents only and no k8s /
Vault / KMS, the upgrade is:

```bash
# Pull the v0.6.0 jar
curl -L -o /opt/anvil/anvil.jar https://github.com/SuperBadLabs/anvil/releases/download/v0.6.0/anvil-0.6.0-standalone.jar
systemctl restart anvil
```

Nothing else changes. The `:k8s-agent`, `:vault-backend`,
`:cloud-kms-backend`, and `:dockerfile-multistage` flags graduate to
default-on, but each is a no-op without operator config:

- `:k8s-agent` — only fires when a Jenkinsfile declares
  `agent { kubernetes { ... } }`. Without it, docker / local agents
  behave identically to v0.5.x.
- `:vault-backend` + `:cloud-kms-backend` — `install!` refuses to take
  over the SecretBackend chain unless `:anvil.vault/url` or
  `:anvil.kms/...` keys are present in `anvil.edn`. The local-disk
  credential store stays active and credentials resolve exactly like
  v0.5.x.
- `:dockerfile-multistage` — single-stage `agent { dockerfile { ... } }`
  builds (no `:target` in the IR) hash identically to v0.4 AN6-3.
  Flipping default-on never changes a single-stage image tag.

## 2. New feature flags (closed-by-default)

The AN8 Jenkinsfile-fidelity flags stay closed through v0.6.0 ship.
Opt in per deployment in `anvil.edn`:

```clojure
{:anvil.features/tools-directive          true   ; AN8-1 + AN8-3
 :anvil.features/parameters-defaults      true   ; AN8-2
 :anvil.features/scm-checkout-lifecycle   true}  ; AN8-4
```

**Recommended**: flip these one at a time and re-run your build set
or the wild-corpus to confirm the new translation matches your
Jenkinsfile shapes. None is destructive — worst case is a build
classifies `:unsupported` differently than before.

Why closed by default: these change how anvil interprets common
declarative-pipeline shapes (`tools{}`, `parameters{}`, matrix
composition, implicit `checkout scm`). The change is forward-compatible
with Jenkins's semantics, but a deployment that depended on the v0.5.x
gaps (e.g. operators who explicitly wrote `checkout scm` because anvil
didn't auto-checkout) gets a no-op double-checkout flag-on. AN8-4's
idempotent guard handles that case but you may prefer to verify first.

## 3. New config knobs (anvil.edn)

### `:anvil.tools/images` (AN8-1)

Operator mapping from Jenkinsfile `tools{}` declarations to pre-baked
docker images:

```clojure
{:anvil.tools/images
   {"maven-3.9-jdk-17"               "maven:3.9-eclipse-temurin-17"
    "maven_3_latest+jdk_17_latest"   "maven:3.9-eclipse-temurin-17"
    "maven-3.9-jdk-21"               "maven:3.9-eclipse-temurin-21"
    "*"                              "maven:3.9-eclipse-temurin-17"}}  ; wildcard fallback
```

The resolver tries multiple candidate keys (raw-join, canonical-sort,
type-version composite, per-tool, then `*` wildcard) and stops on the
first match.

**Per the v0.6 anti-goal: no anvil-managed JDK installer.** anvil
substitutes the operator-mapped image; it doesn't download JDKs
itself.

### `:anvil.parameters/defaults` (AN8-2)

Per-job operator overrides on top of the Jenkinsfile's
`parameters{choice}` defaults:

```clojure
{:anvil.parameters/defaults
   {"wild-apache-activemq" {"nodeLabel" "ubuntu"
                            "jdkVersion" "jdk_17_latest"}}}
```

Layer order (last wins): translator-extracted defaults → operator
overrides → runtime trigger params.

### `:anvil.k8s/kubeconfig-path` (T1)

Override of the K8sBackend's kubeconfig file:

```clojure
{:anvil.k8s/kubeconfig-path "/path/to/kubeconfig"}
```

Fallback order: this key → `KUBECONFIG` env → `~/.kube/config`.
Memoized for JVM lifetime — restart to pick up an edit.

### `:anvil.vault/url` + `:anvil.vault/token-path` (T2)

Hashicorp Vault KV v2 mode:

```clojure
{:anvil.vault/url        "https://vault.example.com"
 :anvil.vault/token-path "/var/run/secrets/vault-token"}
```

Without both keys, the Vault adapter no-ops and credentials continue
to resolve via the local-disk store.

### `:anvil.kms/...` (T2)

Cloud-KMS adapter. AWS-first; provider stubs for GCP + Azure ship in
v0.6.x. See `docs/secrets/vault-kms-backends.md` for the full schema.

## 4. Behavioral changes

### Build-overrides hot-reload (T4)

In v0.5.x, editing `:anvil.build-overrides` required a daemon restart.
In v0.6, a daemon thread watches `anvil.edn` and clears the cache on
modification — the next build sees the new shape automatically.

**No new flag** — always-on, crash-safe, no-op when anvil.edn is
classpath-bundled rather than on-disk.

### SecretBackend protocol (T2)

The internal credential-resolution path has been refactored behind
the `anvil.secrets/SecretBackend` protocol. The default-installed
LocalDiskBackend wraps the existing v0.5.x store, so external
behavior is unchanged. Operators writing custom adapters can now
plug in via the protocol.

### SCM-checkout-before-stage-1 (AN8-4, flag-gated)

When `:scm-checkout-lifecycle true`, declarative pipelines that don't
declare an explicit `checkout scm` step get an implicit checkout
between pipeline parse and stage 1 — matching Jenkins's declarative
lifecycle. Closes the universal "stage 1 runs against empty workspace
→ `git clean -fxd` exit 128" failure from the AN7-5c receipt.

Idempotent: skips if the workspace already has a matching `.git`
directory. Won't double-checkout.

## 5. Deprecations

None. v0.6 is purely additive at the public API level. Internal
changes (dispatcher refactors for k8s + AN8) don't surface to
operators.

## 6. Wild-corpus impact

See `docs/jenkins-compat/wild-corpus-honest-receipt.md` for the v0.6.0
section with per-build verdicts after the T6 rerun. Per AV6-5, the
aspirational target is ≥ 8 of 14 type-A or type-B `:success`; honest
receipt either way per AV6-6 / AV6-8.

## 7. Rollback

`/opt/anvil/anvil.jar.previous` holds the previous version's jar (the
auto-redeploy timer writes it before swapping in the new jar). To
roll back:

```bash
sudo cp /opt/anvil/anvil.jar.previous /opt/anvil/anvil.jar
sudo systemctl restart anvil
```

All v0.6 features no-op gracefully without their config keys, so a
rollback to v0.5.x is also clean if anvil.edn was edited.
