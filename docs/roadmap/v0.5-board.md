# anvil v0.5 — Scale + Honesty Execution Board

> **Premise.** v0.4.1 closed the leapfrog promises (flaky, container-as-step,
> AI authoring, SLSA provenance) and the AN6 honesty receipts. v0.4.2 added
> CPU-weighted fleet apportionment + the cassandra Ant fix (PR #72, #75, #76).
> What's left is **two threads**, both real:
>
> 1. **The scale thread** — features the v0.4 board explicitly deferred:
>    remote build cache (Bazel-style content-addressed step caching),
>    cost-per-minute reporting, GitLab MR + Bitbucket PR-check support
>    (the v0.3.1 deferral that survived two trains without landing), and
>    the **first Chengis 0.1** release (multi-tenant, RBAC, audit, SSO).
> 2. **The honesty thread (AN7 series)** — the v0.4.1-T6 + v0.4.2 fleet
>    reruns gave us 1/14 `:success` (apache-cassandra via synthetic Ant).
>    The other 13 reds each have a named blocker. The AN7 series attacks
>    them in effort order; the concrete target is **≥ 5 of 14 :success** by T6 (with 9-10/14 aspirational per AV5-8).
>
> v0.5 ships **both threads** in the same window. AV5-1 carries forward
> AV4-1's premise: leapfrog and honesty braid; honesty doesn't gate
> leapfrog ship, but the AN7 series gets shipped opportunistically with
> every tranche window.
>
> **What v0.5 is NOT.** Not Vault / Cloud-KMS secret backends (deferred
> to v0.6 per the v0.4 After-Preview — same deferral that's been live
> since the AV3-6 train). Not hermetic build (SLSA L4 — v0.6). Not
> Kubernetes-agent runtime (v0.6 — unblocks eclipse-epsilon + mojarra).
> Not user-facing AI suggestion shipping (v0.4.1's T3 closes that; v0.5
> doesn't add new AI surface).
>
> **Window.** 10 weeks. T0 (~½), T1–T4 (~1–1½ wk each), T5 AN7 series
> rides in parallel across T1–T4, T6 wild-corpus rerun + T7 ship (~1 wk
> combined). Pile-Drive Mode applies — once a tranche is loaded, drive
> its PRs to merge.
>
> **Deploy posture.** v0.4 finished the public deployment gradient
> (step 5 full launch). v0.5 development runs against the production
> dogfood instance at heman:8765 (auto-redeploy timer hot-swapping master
> every 5 min). The fleet (`heman:8767` + `mario:8767` + `luigi:8767`
> with PR #72's CPU-weighted apportionment) is the wild-corpus
> verification harness; the production daemon is the dogfood signal.

## Locked decisions (AV5-series)

| ID | Decision | Why |
|---|---|---|
| **AV5-1** | **v0.5 ships both threads.** Scale (T1–T4) and honesty (T5 AN7 series) braid in the same release. Continues AV4-1's premise — the public wild-corpus receipts named the AN7 gaps; we don't abandon them silently. | The v0.4.1-T6 receipt put cassandra at 1/14 `:success` publicly; the v0.5 board owns lifting that number. |
| **AV5-2** | **Remote build cache is content-addressed at the step level**, NOT the build level. Cache key = `(image-digest, command, env-fingerprint, input-tree-digest)`. Persisted to a local + (optional) remote object store. | Build-level cache misses on every commit; step-level cache hits across commits when the upstream maven dependencies haven't moved. Matches Bazel's semantics. |
| **AV5-3** | **Cost-per-minute uses wall-clock × declared host rate**, not CPU-time × inferred rate. Operators declare host rates in `anvil.edn`; anvil sums wall-time per build and reports `$ × min`. | Wall-clock is what operators pay (cloud VM hourly rates). CPU-time hides parallelism wins. |
| **AV5-4** | **GitLab MR + Bitbucket PR-check reuse the existing GitHub Checks subscriber pattern.** New `anvil.integration.gitlab-subscriber` + `anvil.integration.bitbucket-subscriber` modules; same `:build-started` / `:build-done` bus topics. | The v0.4 T3.4 path works. Don't reshape it for two new providers — adapt it. |
| **AV5-5** | **Chengis 0.1 ships its own repo + jar.** Not bundled into anvil. anvil v0.5 adds the optional `chengis-rbac` adapter that hooks anvil's auth path; without chengis present, anvil stays single-tenant exactly as today. | Multi-tenant is a different product. Bundling now would couple anvil's release cadence to chengis 0.1's; we want the opposite. |
| **AV5-6** | **AN7 series honors `:unsupported` over fake `:success`.** When in doubt, ship an honest `:unsupported :rule-name` with a receipt. PR #75's cassandra synthetic is the precedent — type-B (synthetic shim) `:success` is acceptable AND labeled. | Continues the AN4-1 honesty contract. Going backward on honesty would invalidate every receipt we've shipped since v0.3.3. |
| **AV5-7** | **Honest-thread AN7 tickets land alongside scale, not gating.** A missing AN7 fix doesn't block T7 ship; a missing scale tranche does. | Same posture as AV4-7. Leapfrog *is* the v0.5 promise; AN7 is *continuation*. |
| **AV5-8** | **The wild-corpus 9-10/14 `:success` target is aspirational, not gating.** Real ceiling depends on which AN7 tickets land cleanly. Receipt at T6 captures what actually happened, not what we hoped. | The AN6 series hit similar reality — some tickets shipped as `:unsupported` receipts rather than real-pass features. AV5-8 makes that posture explicit upfront. |
| **AV5-9** | **Public deployment gradient step 5 (full launch) is in the rear-view.** v0.5 is post-launch maintenance: no new gradient steps. | v0.4.x finished the gradient per AV4-9. |

| In | Out |
|---|---|
| Remote build cache (step-level, content-addressed) | Distributed build orchestration (step-level cache ≠ step-level *execution* across hosts; that's v0.6+) |

## Risk register

| ID | Risk | Mitigation |
|---|---|---|
| **R1** | Remote cache invalidation is subtle — wrong key collisions corrupt downstream builds | Cache key includes image digest + env fingerprint + input-tree merkle. Mismatch → cold cache, never wrong cache. Receipt at T1.4 documents the invariants tested. |
| **R2** | Cost-per-minute numbers misread by operators who don't know the rate they declared | UI shows the per-host rate alongside the total. Tooltip explains "based on rates you set in anvil.edn". |
| **R3** | GitLab/Bitbucket APIs differ enough that one adapter ≠ both. | Build GitLab first (T3) — it's closer to the GitHub API shape. Bitbucket gets its own design pass; if too divergent, ship GitLab + a `:bitbucket :deferred` receipt. |
| **R4** | Chengis 0.1 RBAC bleeds into anvil's auth code; coupling that we don't want | The `chengis-rbac` adapter goes behind a feature flag (`:anvil.features/multi-tenant`). Without it, anvil's auth code path is unchanged. |
| **R5** | AN7-2 (`${X}` interpolation) over-eagerly substitutes inside `sh '...'` shell strings (where `${X}` is bash, not Groovy) | Scope the interpolation strictly to declarative-pipeline string contexts (`agent { label }`, `environment { … }`, `parameters` defaults). Leave `sh` step bodies untouched. |
| **R6** | AN7-3 (`:file` credentials) — file-mounting into docker breaks on rootless or remote docker contexts | Use the same `-v $HOST_PATH:$CONTAINER_PATH:ro` flag chengis-core's DockerBackend already uses for workspace mounts. Smoke against rootless + classic docker. |
| **R7** | AN7-4 (AN5-2 `@Library` loader) — naive impl pulls library code on every build; not cache-friendly | Cache library by `(repo-url, ref)` to a local shared dir. Operators can preseed it. Receipt documents the cache eviction policy. |
| **R8** | T6 wild-corpus rerun comes back at 4/14 instead of the 9-10 we targeted | Per AV5-8, the receipt captures honest reality. Numbers we shipped publicly say AN7 work is in-flight, not promised. Receipt-tone is "moved from 1/14 to X/14; here's what's left". |
| **R9** | Chengis 0.1 ship slips, leaving anvil v0.5 to ship without the multi-tenant story | AV5-5 isolates the two: anvil v0.5 ships its own jar regardless. Chengis 0.1 ships when it ships. Comparison post mentions chengis if available, omits otherwise. |

### T1 — Remote build cache (~ 1.5 weeks)

**Goal**: content-addressed step-level caching with local + (optional) remote object store. Cache key = `(image-digest, command, env-fingerprint, input-tree-digest)`.
**Depends on**: T0
**Exit criteria**: a re-run of an unchanged build hits the cache for every step; `:cache-hit` SSE topic fires per step; receipt at `docs/cache/README.md` documents key shape + invariants.

- [ ] **T1.1** — `anvil.cache.key` — pure-fn key derivation: `(image-digest, command, sorted-env-pairs, tree-merkle)` → SHA-256 hex. Tests cover digest stability under reorder + env-removal.
- [ ] **T1.2** — `anvil.cache.local-store` — content-addressed filesystem store at `~/.anvil/cache/<key-prefix>/<key>/{stdout, stderr, exit, artifacts.tgz}`. LRU eviction at configurable max-bytes.
- [ ] **T1.3** — Wire `anvil.cache.lookup` into chengis-core's docker backend dispatch path. On hit: replay stdout/stderr/exit, untar artifacts to workspace. On miss: run, then `anvil.cache.store`. Behind `:anvil.features/cache` flag.
- [ ] **T1.4** — Cache invariants receipt: `docs/cache/invariants.md` — what changes invalidate, what doesn't. Includes a worked example showing why a `mvn install` with the same pom but different test files re-uses the dependency-resolution cache but re-runs the test step.
- [ ] **T1.5** — Optional remote object store adapter: `:anvil.cache/remote {:type :s3 :bucket "..." :region "..."}`. Read-through + write-back. Feature flag `:anvil.features/cache-remote`.
- [ ] **T1.6** — Browser smoke test: trigger a build twice, second run shows cache-hits in the UI for every step; total wall-time < 20% of first run.

## Fleet utilization & parallelism

The 10-week cadence below assumes a single sequential developer. The actual
fleet — **HeMan 32c/56G, Mario 12c/30G, Luigi 56c/123G** — collapses that
significantly. This section maps which tranches can run in parallel, which
must serialize, and which lanes each fleet host should carry. Reading this

**Hard serializations** (cannot parallelize):
- T0 blocks everything (scaffold)
- T1 → T2 (cost needs cache to report `(saved $X via cache)`)
- {T1–T4, AN7-1…5} → T6 (rerun needs everything that's going to ship)
- T6 → T7 (ship needs receipt)

**Everything else parallelizes.** T1, T3, T4, and all of AN7 can ship
independently of each other in any order.

### Parallel lanes — after T0

```
Lane A (cache-cost):       T1 ──────────► T2  (~2.5 wks)
Lane B (integrations):     T3              (~1.5 wks)
Lane C (chengis):          T4              (~1.5 wks)
Lane D (AN7 honesty):      AN7-1 → AN7-2 → AN7-3 → AN7-4 → AN7-5  (~5 wks)
                           (each is a separate PR; D can stream-merge)
```

Lane A is the longest at ~2.5 wks. Lane D is the longest if run serially
(~5 wks), but it can FAN OUT internally — AN7-1 through AN7-5 are
independent PRs.

If we hold to one active reviewer:
- **Critical path with one dev**: Lane A (T0 ½ wk + T1 1.5 wk + T2 1 wk + T6 ½ wk + T7 1 wk) = **5.5 weeks**, vs. the table's 10
- **Critical path with two devs** (parallel B+C+D against A): same 5.5 weeks, but Lanes B/C/D all land by week 4 instead of weeks 6–9

Lane D's internal critical path is **AN7-1 (1 day) → AN7-4 (2 wks)** at
~2.5 wks. AN7-2/3/5 hang off the side.

### Fleet host assignment

The fleet is **a verification harness, not an impl substrate.** Implementation
happens in one editor; the 3 hosts are where the wild-corpus + dogfood
re-verification batches run per-PR. Assigning hosts:

| Host | Role | Why |
|---|---|---|
| **HeMan** (32c) | Primary impl + production dogfood (`:8765`, systemd-managed, auto-redeploy via `redeploy.bb`) | Editor + lein test + the `anvil-self-test` job lives here; redeploy timer hot-swaps master every 5 min. This is where you write the code. |
| **Mario** (12c) | Constrained-host verification (`:8767`, 3 workers) | The "smallest fleet member" lane. Catches over-provisioning bugs the big boxes hide. Best for AN7-2 / AN7-3 receipts where docker behavior under cap matters. |
| **Luigi** (56c) | Heavyweight verification (`:8767`, 14 workers) | The big box. Runs T6 full wild-corpus rerun; absorbs AN7-4's `@Library` cache + multi-build parallel impact. Catches cache-collision bugs in T1 under heavy concurrency. |

Implementation worktrees stay on HeMan. Verification reruns fan out via
`bb scripts/wild-corpus-rerun.bb --fleet=http://heman:8767,http://mario:8767,http://luigi:8767`
(the same v0.5 path we used today).

### Verification matrix — when to use the fleet

| Tranche | Fleet usage | Mode | Why |
|---|---|---|---|
| T0 | None | — | Scaffold only; no runtime change |
| T1 cache | All 3 hosts after T1.6 | Parallel | Cache key must hold across hosts with same image digest; multi-host run proves invariants |
| T2 cost | All 3 hosts after T2.5 | Parallel | Per-host rates need to sum correctly; multi-host build proves accounting |
| T3 GitLab/BB | HeMan only | Serial | PR-check is per-build, not per-host; one host enough |
| T4 chengis | HeMan only | Serial | Multi-tenant adapter is auth-path, no fleet semantics |
| AN7-1 | All 3 hosts (T6-style mini-rerun) | Batch | Verify +4 greens against the same fleet harness T6 will use |
| AN7-2 | Mario + Luigi (skip HeMan) | Parallel | `${X}` interpolation impact shows in the wild-corpus's parameter-heavy builds; HeMan adds nothing |
| AN7-3 | HeMan + Luigi | Parallel | File credentials interact with docker `-v` mounts; verify on two different docker daemon configs |
| AN7-4 | All 3 hosts | Parallel | `@Library` library cache should hit cross-host; verify by pre-seeding Luigi's lib cache + watching HeMan/Mario hit it remotely (optional) |
| AN7-5 | All 3 hosts | Parallel | Resource limits are per-host; tuning must show on all three to count |
| T6 | All 3 hosts | Batch (full wild-corpus) | The headline number |
| T7 | HeMan production dogfood | Serial | Auto-redeploy → `anvil-self-test` blue verification |

"Mini-rerun" = a 4–8-build subset that exercises just the target tickets,
not the full 14. Cheaper than a T6-grade rerun; useful per PR.

### Batch operations

Three operations naturally batch:

1. **AN7-1 burst PR** — apache-maven synthetic + activemq/zookeeper/jdt-core
   skip-test synthetics + jkube credential. One PR, one mini-rerun across
   all 3 hosts, one receipt entry. Target: 1-day burst lands +4 greens.

2. **T6 full wild-corpus rerun** — all 14 builds, CPU-weighted Hamilton
   apportionment across HeMan/Mario/Luigi via PR #72's path. Single
   `bb scripts/wild-corpus-rerun.bb --fleet=...` invocation produces the
   v0.5 receipt entry.

3. **Cache invariants test sweep (T1.4)** — same build replayed 3× across
   the fleet with controlled deltas (no change → all hit; image change →
   all miss; pom change → some miss); produces the cache-invariants
   receipt as a single batch run.

```
Week 1:  T0 ──┐
              ├── AN7-1 burst (1 day, parallel during T0; ships +4 greens)
              │
Week 2:  T1 begins ─┐                                AN7-2 ─┐
                    │                                       │
Week 3:  T1 continues + cache fleet-verify ──┐      AN7-2 ──┘ +1-3 greens
                                             │
Week 4:  T1 ships ──► T2 begins              AN7-4 begins ─┐ AN7-3 ─┐
                                                           │        │

                    │

                                             AN7-4 ──┘ +2 greens

Week 7:  AN7-5 (opportunistic) + AN7-6 receipt
```

That's **9 weeks at single-dev**, **6-7 weeks if Lane B (T3) + Lane C (T4) +
Lane D (AN7-2/3/4) get separate reviewers**.

The fleet's biggest contribution isn't capacity for impl — it's **the
verification-rerun budget**. Every AN7 PR can land with a fresh
wild-corpus mini-rerun receipt at PR-review time, not just at T6. That
tightens the AN7 feedback loop from "wait until T6 to know if this
helped" to "see the green count move on the PR".

## Anti-goals (resist)

- **Do not start v0.6 features in v0.5.** K8s-agent is the obvious temptation; refuse it. The cassandra synthetic stays a type-B until v0.6.
- **Do not break AV5-6 honesty.** No fake `:success` to hit the AV5-8 number; honest `:unsupported` is acceptable, fake-green is not.
- **Do not couple anvil's release to chengis 0.1.** Adapter is optional; anvil v0.5 ships regardless of chengis state.
- **Do not break the page-load budgets.** p50 < 50 ms still holds with cost dashboard + cache-hit pill + MR/PR-check panels.
- **Do not over-cache.** Cache invariants get a receipt (T1.4) explaining what's safe vs not. When in doubt, cold cache.
- **Do not let AN7-2 leak into `sh` step bodies.** Groovy `${X}` ≠ bash `${X}`. Per R5.
- **Do not announce v0.5 publicly until T7 ships the tag.** v0.4 finished the gradient; v0.5 is post-launch maintenance — no "soft launch" needed.
