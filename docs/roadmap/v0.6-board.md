# anvil v0.6 — Hermetic-Adjacent + Kubernetes + Fidelity Execution Board

> **Premise.** v0.5.0 shipped the scale tranche (cache, cost, MR/PR,
> multi-tenant) plus the AN7 honesty series, landing wild-corpus at
> 6/14 type-B `:success`. The AN7-5c receipt (PR #97) put names on the
> remaining blockers: not memory, not credentials — **Jenkinsfile
> shape fidelity** (matrix, tools, parameters, SCM-checkout lifecycle)
> and **runtime expansion** (k8s agents for `cassandra-large` /
> mojarra / epsilon).
>
> v0.6 attacks both:
>
> 1. **The runtime thread** — Kubernetes agents (the v0.6 deferral
>    that's blocked cassandra's real Jenkinsfile + epsilon + mojarra
>    since v0.3), Vault + Cloud-KMS secret backends (deferred since
>    v0.4), and container-as-step multi-stage Dockerfile support.
> 2. **The honesty thread (AN8 series)** — `tools` directive,
>    `parameters { choice }`, matrix-declarative-with-tools
>    composition, SCM-checkout-before-stage-1 lifecycle. These four
>    items collectively gate activemq + zookeeper + (partially)
>    jdt-core's real Jenkinsfile from running.
>
> AV6-1 carries forward AV5-1's premise: leapfrog and honesty braid;
> honesty doesn't gate ship, but the AN8 series gets shipped
> opportunistically with every tranche window.
>
> **What v0.6 is NOT.** Not SLSA L4 hermetic build (v0.7 — needs k8s
> AND signing infra AND SBOM; too much for one window). Not distributed
> step-level execution across hosts (v0.7 — v0.5's cache is content-
> addressed; cross-host execution lifting is the natural follow-up).
> Not Gerrit / Azure DevOps PR integrations (v0.6.x). Not Chengis 0.2
> per-tenant resource quotas (Chengis 0.2 standalone window). Not new
> user-facing AI surface.
>
> **Window.** ~10 weeks. T0 (~½), T1 K8s is heaviest (~2 wk), T2-T4
> ~1-1½ wk each, T5 AN8 rides parallel across T1-T4, T6 + T7 ship
> combined (~1 wk).
>
> **Deploy posture.** v0.5 finished post-launch maintenance — v0.6
> continues to run against the production dogfood at `heman:8765`
> (auto-redeploy timer hot-swapping master every 5 min). Fleet
> (`heman:8767` + `mario:8767` + `luigi:8767`) remains the wild-corpus
> verification harness. K8s tranche needs a single-node `kind`
> cluster on the dogfood host (already running per `kindest/node`
> containers visible in `docker ps`).

## Locked decisions (AV6-series)

These are not up for discussion mid-execution. If one needs to change,
stop the program, change the decision, restart.

| ID | Decision | Why |
|---|---|---|

Going silent on those names would invalidate the v0.5.x honest-receipt contract. |

| **AV6-7** | **AN8 honest-thread tickets land alongside infra, not gating.** A missing AN8 fix doesn't block T7 ship; a missing K8s or Vault tranche does. | Direct lift from AV5-7. |
| **AV6-8** | **The 8/14 wild-corpus target is aspirational, not gating.** T6 receipt captures what actually happened. Per AV5-8 / AV6-5 — receipt-driven targets ride post-shipment, never gate it. | Continuation of AV5-8. |

### T1 — Kubernetes agent runtime (~2 wk)

The biggest tranche. Unblocks:
- **eclipse-epsilon** (`agent { kubernetes { yaml '...' } }`)
- **eclipse-mojarra** (k8s + huge YAML declarative)
- **apache-cassandra** real Jenkinsfile (`cassandra-large`-labelled k8s
  agents; retires the PR #75 Ant synthetic for the cassandra label
  that the synthetic accepts)

- [ ] **T1.1** — chengis-core upstream PR: `chengis.engine.backend.k8s/K8sBackend`
      implementing `ExecutionBackend` protocol. Pod-per-step
      (analogous to docker-backend's `:per-step` mode); honors
      `:resource-limits` (maps onto pod resource requests/limits),
      `:env`, `:user`, `:host-user?` (auto-detect host UID/GID).
- [ ] **T1.2** — chengis-core 0.4 release with K8sBackend; anvil dep bump
      from 0.3.x to 0.4.x.
- [ ] **T1.3** — `agent { kubernetes { yaml '...' } }` translator
      (declarative + scripted). Translates Jenkins's `KubernetesPipeline`
      `yaml` block into the chengis-core k8s backend's pod-spec input.
- [ ] **T1.4** — `agent { kubernetes { containerTemplate(...) } }` —
      the structured form Jenkins also accepts. Maps to the same
      pod-spec shape.
- [ ] **T1.5** — `kubectl`-style `kubeconfig` lookup: anvil reads
      `KUBECONFIG` env, falls back to `~/.kube/config`, with operator
      override via `:anvil.k8s/kubeconfig-path` in `anvil.edn`.
- [ ] **T1.6** — T1 receipt: `docs/k8s/anvil-k8s-runbook.md` — how to
      bring up a single-node `kind` cluster, configure anvil to use
      it, trigger a k8s-agent build, observe logs.

Acceptance: a synthetic `agent { kubernetes { yaml '...' } }`
Jenkinsfile runs to `:success` on the dogfood with `kind`. Two type-A
greens on the wild-corpus: epsilon + mojarra (or honest `:unsupported`
receipts if their real Jenkinsfiles need more than basic k8s).

### T2 — Vault + Cloud-KMS secret backends (~1½ wk)

The deferral that's survived since v0.4. operators want secret material
NOT to live on local disk.

- [ ] **T2.1** — `anvil.secrets/SecretBackend` protocol: `(resolve!
      [this id])` returns the secret value (or `nil` if absent).
      `(list-ids [this])` for the admin UI. Default impl wraps the
      existing local-disk store; Vault + KMS are new impls.
- [ ] **T2.2** — `anvil.secrets.vault` — Hashicorp Vault adapter. KV v2
      mode initially (most common). Reads `:anvil.vault/url` +
      `:anvil.vault/token-path` from `anvil.edn`.
- [ ] **T2.3** — `anvil.secrets.kms` — Cloud-KMS adapter (AWS KMS first;
      GCP-KMS + Azure-KeyVault stubs per chengis-core's existing
      cross-cloud pattern). Decrypts encrypted blob references stored
      in `anvil.edn`; the blob itself can live in Git.
- [ ] **T2.4** — Wire both into `h-with-credentials` (PR #84) and
      `h-environment` so secrets resolve via the configured backend
      regardless of credential type. AN7-3 file credentials grow a
      Vault/KMS option alongside the local-disk default.
- [ ] **T2.5** — T2 receipt: `docs/secrets/vault-kms-backends.md` —
      operator runbook for provisioning each backend.

Acceptance: anvil v0.6 with Vault backend configured + a secret stored
in Vault resolves correctly through `withCredentials`; same for KMS.

### T3 — Container-as-step multi-stage Dockerfile (~1 wk)

v0.5 deferred this. Cassandra-real-Jenkinsfile needs it (its dockerfile
agent is multi-stage).

- [ ] **T3.1** — Translator support for `agent { dockerfile { filename
      'Dockerfile' dir 'docker-build' args '--target prod' } }`.
- [ ] **T3.2** — chengis-core/docker-backend honors `:dockerfile-build`
      step type: `docker build` then `docker run` against the built image.
      Caches the image hash per workspace + Dockerfile content so
      successive builds hit the BuildKit cache.
- [ ] **T3.3** — `--target` flag forwarded so multi-stage builds can
      pick the right stage.
- [ ] **T3.4** — Wire into wild-corpus-shim resolution so cassandra-real
      can use this if a `Dockerfile` exists at its workspace root.
- [ ] **T3.5** — T3 receipt: `docs/container-step/dockerfile-agent.md`
      gets the multi-stage section.

Acceptance: cassandra-real-Jenkinsfile (or a synthetic test rig)
builds + runs a multi-stage image and lands `:success`.

### T4 — Build-overrides hot-reload (~½ wk)

Small v0.5.x continuation — operators wanted this.

- [ ] **T4.1** — `anvil.build-overrides` adds a file-watch on
      `anvil.edn` via `babashka.fs/watcher` or
      `java.nio.file.WatchService`. On change, calls `clear-cache!`.
- [ ] **T4.2** — Receipt update in
      `docs/jenkins-compat/an7-5-build-overrides.md` documenting

Acceptance: an operator edits `:anvil.build-overrides`, the next
build sees the new shape without daemon restart.

### T5 — AN8 series — Jenkinsfile fidelity (parallel across T1-T4)

The honesty thread. Each ticket is a focused PR.

- [x] **AN8-1** — `tools { maven 'X' jdk 'Y' }` directive. Translator
      parses tools{} block into structured IR
      (`[{:type :maven :version "X"} {:type :jdk :version "Y"}]`);
      dispatcher resolves the spec through operator-curated
      `:anvil.tools/images` in anvil.edn to a pre-baked docker
      image. Without a mapping, emits `:tools/unmapped` with all
      candidate keys + falls back to the Jenkinsfile-declared
      agent. No anvil-managed JDK installer (per v0.6 anti-goal).
      Receipt: [an8-1-tools-directive.md](../jenkins-compat/an8-1-tools-directive.md).
- [x] **AN8-2** — `parameters { choice(name: 'X', choices: [...]) }`
      defaults propagate into `ctx :parameters` via a three-layer
      merge: translator-defaults < operator-defaults
      (anvil.edn `:anvil.parameters/defaults`) < runtime-params
      (REST/form/webhook trigger payload). The runner pre-parses the
      Jenkinsfile to extract translator defaults, then seeds
      `ctx :parameters` before any stage runs. Receipt:
      [an8-2-parameters-defaults.md](../jenkins-compat/an8-2-parameters-defaults.md).
- [ ] **AN8-3** — matrix-declarative-with-tools composition. The
      matrix block declares its own agent / tools inside each axis.
      Without AN8-3, zookeeper's `matrix { axes { JAVA_VERSION ... }
      tools { ... } }` doesn't compose with the outer pipeline tools{}.
- [ ] **AN8-4** — SCM-checkout-before-stage-1 lifecycle. anvil
      currently runs the first stage's first step against an
      un-checked-out workspace for declarative pipelines without an
      explicit `checkout scm` step. Jenkins's lifecycle implicitly
      runs `checkout scm` before stage 1 for declarative pipelines.
      Without AN8-4, every real Jenkinsfile that omits the explicit
      checkout step fails on `git clean` or `mvn` against an empty
      workspace.
- [ ] **AN8-5** — AN7-1 retirement audit. After AN8-1..4 land, revisit
      each of the four heavies (+ jkube AN7-3) and document which
      shims actually retire as type-A; which stay type-B with updated
      criteria; which stay type-B forever (jdt-core's intrinsic
      Eclipse-compiler-test failures).
- [ ] **AN8-6** — Per-tranche receipts under
      `docs/jenkins-compat/an8-*.md`. Same shape as the AN7-1c jkube
      receipt — what worked, what didn't, what's next.

Acceptance: at minimum 2 of the 4 AN8 fidelity tickets ship; receipt
each. Real-world impact measured at T6.

## Anti-goals (resist)

- **Do not start v0.7 features in v0.6.** SLSA L4 + distributed step
  execution are the obvious temptations. Both are HUGE; either alone
  would consume the v0.6 window. Refuse.
- **Do not break AV6-6 honesty.** No fake `:success` to hit AV6-5's
  8/14 target. Honest `:unsupported` is acceptable; fake-green
  invalidates every receipt since v0.3.3.
- **Do not bundle k8s SDK into anvil.** AV6-2 — chengis-core owns the
  k8s backend; anvil just consumes the protocol.
- **Do not couple Vault + KMS implementations.** Each is its own
  adapter; an operator with only Vault shouldn't pay the KMS-jar
  weight. Same with the inverse.
- **Do not skip the SCM-checkout-lifecycle (AN8-4).** It's the
  universal bug — every real declarative Jenkinsfile expects this
  contract. Skipping it leaves anvil incompatible with the real-world
  Jenkinsfile ecosystem indefinitely.
- **Do not announce v0.6 publicly** until T7 ships the tag. v0.4
  finished the gradient; post-launch maintenance — no "soft launch"
  needed (continuation of AV5-9 / AV6-9).
- **Do not let AN8-1 spawn an anvil-managed JDK-installer.** anvil
  isn't `asdf` / `sdkman`. Operators map `tools { jdk 'X' }` to a
  pre-baked docker image via `anvil.edn` config; anvil doesn't
  download JDKs itself.
