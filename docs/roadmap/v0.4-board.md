# anvil v0.4 — Leapfrog + Honesty Execution Board

> **Premise.** v0.3 closed the seven Tier-1 parity gaps; v0.3.3 closed the
> wild-corpus artifact axis (9,641 jars / 7.4 GB across 12 honestly-classified
> builds). What's left is **two threads**, both real:
>
> 1. **The leapfrog thread** — features Jenkins and GHA *don't* have in 2026:
>    container-as-step that actually composes with matrix, passed-on-retry
>    flaky-test detection wired into the JUnit infra from T1, AI authoring
>    that scaffolds and explains pipelines, and SLSA L3 provenance with
>    sigstore-signed in-toto attestations on every artifact.
> 2. **The honesty thread** — the v0.3.3 wild-corpus receipt named six
>    specific translator/runtime gaps by build (apache-activemq's
>    nested-label-params, apache-cxf + eclipse-epsilon's matrix shape,
>    apache-cassandra's dockerfile-agent, apache-maven's `mavenBuild`,
>    eclipse-jkube's GPG-subkey credential UX, apache-hbase's long-build
>    cap). Each is a real blocker for one real OSS project.
>
> v0.4 ships **both threads** in the same window. Each tranche advances
> the leapfrog story without abandoning the honesty receipts.
>
> **What v0.4 is NOT.** Not remote build cache (Bazel-style content-addressed
> step caching; deferred to v0.5 — needs more soak). Not GitLab MR / Bitbucket
> PR-check support (v0.3.x). Not Vault / Cloud-KMS secret backends (v0.3.x).
> Not multi-tenant / RBAC / SSO (Chengis 0.1).
>
> **Window.** 10 weeks. T0 (~½), T1–T4 (~1–1½ wk each), T5 AN6 series rides
> in parallel across T1–T4, T6 wild-corpus rerun + T7 ship (~1 wk combined).
> Pile-Drive Mode applies — once a tranche is loaded, drive its PRs to merge.
>
> **Deploy posture.** First public anvil deploy began with v0.3.0 (private
> VPS shakedown, per the deployment gradient). v0.4 development runs against
> CI green from TR4 and tracks the deployment gradient's later steps — soft
> launch lands during T6/T7.

## Locked decisions (AV4-series)

These are not up for discussion mid-execution. If one needs to change,
stop the program, change the decision, restart.

| ID | Decision | Why |
|---|---|---|
| **AV4-1** | **v0.4 ships both threads.** Leapfrog (T1–T4) and honesty (T5 AN6 series) braid in the same release. Honesty work doesn't gate the leapfrog tranches; leapfrog work doesn't displace AN6 tickets. | The v0.3.3 receipt named the AN6 gaps publicly. Silently abandoning them to chase leapfrog reads as "we already moved on from the honest classification thread." We didn't. |
| **AV4-2** | **Container-as-step reuses chengis-core's `DockerBackend` + installer matrix.** No new container abstraction in anvil. The AN5-3 plumbing already exists; T2 wires Jenkinsfile `container {…}` blocks into it. | chengis-core 0.3.0 already ships Temurin + Maven + Gradle + Node installers and the DockerBackend bridge. Reinventing here would be unforced. |
| **AV4-3** | **Flaky-test = passed-on-retry analysis ONLY at v0.4.0.** No statistical models, no time-series anomaly detection. A test that passed on a retry within the same build = flaky. | The simplest correct definition. Covers ~80% of operator-observable flake. Statistical models can layer on in v0.4.x. |
| **AV4-4** | **AI authoring is local-first.** `anvil init / explain / optimize` call the Anthropic API via `ANTHROPIC_API_KEY` from env. No hosted anvil service, no proxied calls. Operator's key, operator's bill. | Anvil is single-team self-host; bundling a hosted AI dependency would invert that posture. Local-first also keeps the operator's source code out of any shared service path. |
| **AV4-5** | **SLSA L3 provenance via sigstore/cosign with Fulcio ephemeral keys.** No proprietary key infra, no anvil-hosted signing service. | Sigstore is the 2026 OSS standard. Fulcio's keyless flow means operators don't manage long-lived signing keys. |
| **AV4-6** | **Remote build cache deferred to v0.5.** Bazel-style content-addressed step caching needs more soak than the v0.4 window allows; getting it wrong is worse than not shipping it. | A broken cache produces silently-wrong builds, the single worst CI failure mode. v0.4 keeps the trust intact. |
| **AV4-7** | **Honest-thread AN6 tickets land alongside leapfrog, not gating.** A missing AN6 fix doesn't block T7 ship; a missing leapfrog tranche does. | Tier of expectation: leapfrog *is* the v0.4 promise; AN6 is *continuation*. Both ship if possible; leapfrog ships regardless. |
| **AV4-8** | **chengis-core bumps to 0.4.0 if AN6-3 (dockerfile-agent) lands; else stays 0.3.x.** AN6-3 adds `chengis.tools.dockerfile`; that's a public-API addition that warrants a minor bump. | Library surface change = minor bump per the chengis-core CHANGELOG convention. |
| **AV4-9** | **Public deployment gradient steps 2–4 happen during v0.4.** Step 2 (auth-walled friends) opens after T0; step 3 (DNS, no announcement) after T4; step 4 (soft launch: HN Show / blog post) before T7 ship. | The v0.3 board said "soft launch step 4 starts after v0.4.0 ship"; revising to start *before* ship so the public moment carries v0.4's leapfrog story rather than v0.3.3's parity story. |
| **AV4-10** | **All v0.4 features land on `superbadlabs/anvil/master` via PR + green CI.** `--admin` only with a documented org-policy edge case. | Same as AV3-10. Sustainable. |

## Scope guardrails

| IN (v0.4.0) | OUT (deferred to v0.5 or later) |
|---|---|
| Flaky-test detection (passed-on-retry; T1 JUnit infra reuse) | Statistical flake models / time-series anomaly detection (v0.4.x) |
| Container-as-step (`container 'maven:…' { sh '…' }`) via chengis-core DockerBackend | Container-as-step with custom build context / multi-stage Dockerfile (v0.5) |
| AI authoring (`anvil init`, `anvil explain`, `anvil optimize`) | Hosted AI service / proxied model calls (never — AV4-4) |
| SLSA L3 provenance (sigstore/cosign, in-toto v1, Fulcio keyless) | SLSA L4 hermetic build environment (v0.5+) |
| AN6 series — translator/runtime gaps named in v0.3.3 wild-corpus receipt | Other wild-corpus builds not in the named-six (case-by-case) |
| Wild-corpus rerun → target ≥ 4 `:success` (up from 1) | Wild-corpus expansion beyond current 12 builds |
| chengis-core 0.4.0 IF AN6-3 lands (else 0.3.x patches) | chengis-core leapfrog work (no new public-API additions beyond AN6-3) |
| New SSE event topics: `:flaky-flagged`, `:container-step-started`, `:ai-suggested`, `:provenance-attested` | Bus refactor / SSE protocol changes (TU1 design holds) |
| Docs: one .md per leapfrog feature + AN6 series receipt | Vault / Cloud-KMS / GitLab / Bitbucket integration docs |

If you find yourself in the OUT column mid-tranche, file an issue, link
the AV4 decision, and back out.

## Risk register

| ID | Risk | Mitigation |
|---|---|---|
| **R1** | Container-as-step interacts subtly with declarative matrix (T4 from v0.3): each cell may want a different image | Design T2 with matrix-cell scope from the start; smoke test = a 2×2 matrix where each cell requests a different image |
| **R2** | Flaky-test detection false positives — a test that failed once due to a real intermittent infra bug shouldn't be tagged "flaky forever" | Tag flake at the *build* level (passed-on-retry within build), not job-level (always-flaky). Aggregate at job-level only for the dashboard "most flaky" list, with a 30-build window |
| **R3** | AI authoring leaks proprietary repo code to Anthropic API | `anvil explain` / `optimize` send Jenkinsfile content only, never workspace files. Document this prominently. Operator opts in per-job via `:anvil.ai/explain-enabled?` |
| **R4** | SLSA provenance sigstore flow needs network access to Fulcio + Rekor; offline / air-gapped operators block | Provide `:anvil.provenance/offline-key <path>` fallback (operator-managed long-lived key); document the trust trade-off |
| **R5** | AN6-1 static-first-choice fallback works for apache-activemq but might wrongly auto-select for jobs where the first choice is a placeholder | Honor `parameters { choice { ... } }` defaultValue (if any); fall back to first choice with a recorded `[:agent/inferred-from-choice <chosen>]` effect for visibility |
| **R6** | AN6-3 dockerfile-agent: building a Dockerfile from repo can take minutes; first-build penalty unexpected to operators | Cache by Dockerfile sha + repo head sha; document the first-build cost; show "building agent image (1st of N)..." in console |
| **R7** | AN6-4 mavenBuild shared-lib step — every shared-lib step is a new compat surface | Honest `:unsupported step.mavenBuild` ship if the impl is non-trivial; document the per-step compat gap shape |
| **R8** | UI page weight grows: flaky dashboard + provenance pill + AI explain button | Hold pages under TU0.7 budgets (p50 < 50 ms). Re-bench in T7.2. Reject UI work that breaches budget without a clear amortizing benefit |
| **R9** | Sigstore client library footprint (cosign Java client is heavy) | If footprint > 5 MB on the uberjar, shell out to host `cosign` binary instead; document the dependency |
| **R10** | First wild-corpus rerun post-T5 reveals new gaps not in the AN6 list | Receipt-style write-up names them; not a regression — by definition they were latent until earlier gaps cleared. Defer to v0.4.x board |

### T1 — Flaky-test detection (1 week)

**Goal**: A test that passed on retry within the same build gets flagged. The job page shows a "Flaky tests" widget; a global dashboard at `/flaky` lists the top flaky tests across the instance with their 30-build pass-rate sparkline.

**Depends on**: T0; reuses T1 JUnit infra from v0.3
**Exit criteria**: a build that runs `retry(3) { sh 'mvn test' }` and passes on attempt 2 has its previously-failing tests tagged `:flaky? true` in `test_results`; the job page surfaces "3 flaky tests this build"

- [ ] **T1.1** — `anvil.flaky/detect` — analyze `test_results` rows for the same `(build-id, test-id)` pair: if any attempt failed but a later attempt in the same build succeeded, mark `:flaky? true`. Also surface `:retry-count`
- [ ] **T1.2** — DB schema: add `flaky?` (bool, default false) + `retry_count` (int, default 0) columns on `test_results`. Migration as Chengis-style migration file. Backfill: existing rows stay `:flaky? false`
- [ ] **T1.3** — `anvil.web.views.flaky` — dashboard view: top 20 flaky tests across the instance with 30-build pass-rate sparkline, "first flagged" + "last seen" columns. Per-job flaky widget on `/jobs/<j>`
- [ ] **T1.4** — SSE event: `:flaky-flagged {test-id, job, build}` published when T1.1 marks a test flaky; build-page widget swaps from "(analyzing…)" to flagged list
- [ ] **T1.5** — Jenkinsfile compat: `retry(N) { steps }` IR already exists from TX11A; ensure `test_results` rows carry the attempt index so T1.1 has its substrate. No new translator work expected; verify with corpus
- [ ] **T1.6** — Tests: 4 retry-shapes (passes 1st, passes 2nd of 3, fails all 3, mixed test pass/fail across attempts). Browser test for `/flaky` dashboard

### T2 — Container-as-step (1.5 weeks)

**Goal**: A Jenkinsfile with `steps { container 'maven:3.9-eclipse-temurin-21' { sh 'mvn package' } }` runs the wrapped step inside the named image via chengis-core's `DockerBackend`. Reuses AN5-3 plumbing. Composes with declarative matrix — each matrix cell may declare a different container.

**Depends on**: T0; reuses chengis-core ≥ 0.3.0 DockerBackend
**Exit criteria**: a build using `container { sh }` produces real, host-readable artifacts under `target/`; a 2×2 matrix with per-cell containers (`maven:3.9` for JDK17, `maven:3.9-eclipse-temurin-21` for JDK21) shows 4 cells each with their image visible in the build console

- [ ] **T2.1** — Translator: parse Jenkins-Pipeline `container 'image' { … }` step form in `anvil.compat.jenkins.translator`. Produce IR `[:container/wrap {:image …, :body <steps-ir>}]`
- [ ] **T2.2** — Dispatcher: when `:container/wrap` IR encountered, route the body's `sh` steps through chengis-core's `DockerBackend` with the named image, mounting workspace at the same path the host sees it (matches AN5-3c label-routing pattern). Container exit non-zero → step exit non-zero (no swallowing)
- [ ] **T2.3** — Env propagation: CI=true, BUILD_NUMBER, BUILD_ID, JOB_NAME, WORKSPACE etc. forwarded into the container exactly as the host shell would see them. Document the propagation list in `docs/container-step/env.md`
- [ ] **T2.4** — Container-as-step × matrix interaction: each matrix cell's `container` declaration is honored independently. Tested via a sample Jenkinsfile that declares `agent none` at the top-level + per-stage container blocks
- [ ] **T2.5** — Real-artifact receipt: a sample apache-camel-style build using `container { sh 'mvn -B package' }` produces host-readable jars; receipt at `benchmarks/results/v0.4-container-step-receipt.md`
- [ ] **T2.6** — Tests: 3 Jenkinsfile shapes (single container, container + nested sh, container per matrix cell). Browser test for console "running in maven:3.9…" header
- [ ] **T2.7** — Docs: `docs/container-step/overview.md` (operator-facing), `docs/container-step/env.md` (env propagation list), `docs/container-step/composes-with-matrix.md` (the matrix-cell-image pattern)

### T3 — AI authoring (1.5 weeks)

**Goal**: `anvil init` scaffolds a Jenkinsfile from a repo (detecting language, framework, build tool). `anvil explain <Jenkinsfile>` produces a plain-English description of what the pipeline does. `anvil optimize <Jenkinsfile>` suggests improvements (parallelism, container-step, caching). All call the Anthropic API via `ANTHROPIC_API_KEY` from env.

**Depends on**: T0
**Exit criteria**: `anvil init` in an empty repo with `pom.xml` produces a working Jenkinsfile that this anvil instance can run; `anvil explain` of a real Jenkinsfile returns a coherent description in under 10s; `anvil optimize` returns ≥ 1 actionable suggestion for a non-optimal Jenkinsfile

- [ ] **T3.1** — `anvil.ai.client` — Anthropic API client (HTTP only, no SDK). Reads `ANTHROPIC_API_KEY` from env. Model: `claude-sonnet-4-5` default, overridable via `:anvil.ai/model`. Streaming responses to stdout for CLI; buffered for SSE
- [ ] **T3.2** — `anvil.ai.repo-context` — scan repo for languages (file extension counts), package files (`pom.xml`, `package.json`, `Cargo.toml`, `.tool-versions`), CI hints (existing `.github/workflows/*`, `Jenkinsfile`, `.gitlab-ci.yml`). Returns structured context for the prompt
- [ ] **T3.3** — CLI: `anvil init` (scaffold Jenkinsfile from repo-context), `anvil explain <path>` (describe in plain English), `anvil optimize <path>` (suggest improvements). Each prints "Calling Claude API…" header, streams output, exits 0 on success
- [ ] **T3.4** — SSE event: `:ai-suggested {job, build, suggestions}` published when `anvil optimize` runs from the UI's "Optimize" button (T3.5)
- [ ] **T3.5** — UI: "Explain this Jenkinsfile" button on `/jobs/<j>` page — opens a modal that streams the explanation. "Optimize" button does the same with optimization suggestions
- [ ] **T3.6** — Tests: stub-client tests for prompt shape + response parsing (no real API calls in CI). One real-API smoke test gated behind `ANVIL_AI_SMOKE_API=1` env var, opt-in only
- [ ] **T3.7** — Docs: `docs/ai-authoring/overview.md`, `docs/ai-authoring/api-key-setup.md`, `docs/ai-authoring/what-gets-sent.md` (privacy / data-flow doc — see R3)

### T4 — SLSA L3 provenance (1 week)

**Goal**: Each artifact emitted by a build gets a sigstore-signed in-toto v1 provenance attestation written beside it as `<artifact>.intoto.jsonl`. The build page surfaces a "Provenance: ✅ attested" pill linking to the attestation download. `anvil provenance verify <artifact>` CLI verifies offline.

**Depends on**: T0
**Exit criteria**: a build that produces `target/my-app-1.2.3.jar` also produces `target/my-app-1.2.3.jar.intoto.jsonl` containing a sigstore-signed in-toto v1 statement that names the build's git sha, builder identity, and source materials; `anvil provenance verify` returns 0 for a real attestation and non-zero for a tampered one

- [ ] **T4.1** — `anvil.provenance/build-statement` — construct in-toto v1 statement from the build record (subject = artifact sha256, predicate = slsa-provenance/v1 with `builder.id`, `runDetails.metadata.invocationId`, `buildDefinition.externalParameters` from job config). Tested in isolation with sample build records
- [ ] **T4.2** — `anvil.provenance/sign` — sigstore cosign path. Default: Fulcio keyless flow (uses OIDC token from configured identity provider; for self-host without OIDC, fall back to env-supplied long-lived key). Writes JSON-Lines attestation
- [ ] **T4.3** — Dispatcher hook: post-build artifact scanner emits `:provenance/attest` IR; the artifact emit pipeline writes `{artifact}.intoto.jsonl` beside each `archiveArtifacts`-matched file
- [ ] **T4.4** — Build page UI: "Provenance: ✅ attested (3 artifacts)" pill, click expands to the per-artifact attestation list with download links
- [ ] **T4.5** — SSE event: `:provenance-attested {build, artifact, sha256}` published per attested artifact; UI pill swaps from "(signing…)" live
- [ ] **T4.6** — Verify CLI: `anvil provenance verify <artifact>` — reads the sibling `.intoto.jsonl`, calls cosign verify against Fulcio's CT log or the configured long-lived key. Exit 0 = verified; non-zero = mismatch/tampered with diagnostic
- [ ] **T4.7** — Tests: provenance round-trip (sign → verify), tampered-artifact rejection, sibling-file not-found graceful error. Docs: `docs/provenance/overview.md`, `docs/provenance/sigstore-setup.md`, `docs/provenance/offline-key-fallback.md`, `docs/provenance/verify-cli.md`

### T5 — AN6 honesty series (rides parallel with T1–T4, ~3 weeks total)

**Goal**: Close the v0.3.3 wild-corpus receipt's six named translator/runtime gaps. Each is a small, scoped ticket; together they should lift ≥ 3 builds from `:unsupported` or honest-but-degraded `:failure` to `:success` in the post-T5 wild-corpus rerun.

**Depends on**: T0; AN6-3 may bump chengis-core to 0.4.0 (per AV4-8)
**Exit criteria**: wild-corpus rerun (T6) shows ≥ 4 `:success` (up from 1); 0 `:unsupported translator.body-skipped`

- [ ] **AN6-1** — Parameter-driven nested label (apache-activemq). Translator change: parse `parameters { choice { name <n>; choices [...] } }` block at translate time; for an `agent { label { label params.<n> } }` shape, use the choice's `defaultValue` or first listed choice as the static label. Emit `[:agent/inferred-from-choice <chosen>]` effect for visibility. Honest `:agent/degraded :param-driven-label` fallback if no `parameters` block is parseable. Receipt: update `an5-7-activemq-receipt.md` with the fix landing.
- [ ] **AN6-2** — cxf / epsilon matrix shape (`translator.body-skipped`). Extend `anvil.compat.jenkins.matrix-declarative/parse-matrix-call` for the deeper-nesting variant these two builds use (matrix-of-matrix-or-conditioned-axes). Tests against minimal fixtures extracted from both real Jenkinsfiles. Was AN5-6.5 in session notes.
- [ ] **AN6-3** — Dockerfile-agent support (apache-cassandra + the general `agent { dockerfile … }` shape). New `chengis.tools.dockerfile` namespace in chengis-core (warrants 0.4.0 bump per AV4-8): given a workspace Dockerfile path, run `docker build` against it with the repo as build-context, tag with a content-hash, register as an ephemeral label, route through `DockerBackend` (existing AN5-3c path). Cache key = Dockerfile sha256 + git head sha. First-build cost documented in `docs/jenkins-compat/dockerfile-agent.md`.
- [ ] **AN6-4** — `mavenBuild` shared-lib step (apache-maven). Two options: (a) implement the shared-libs `mavenBuild` adapter to route to `mvn` directly with the build-step's params translated, or (b) honest `:unsupported step.mavenBuild` with a receipt explaining the shared-lib step contract gap. Decision goes to the AN6-4 PR description; default to (b) if the impl > 2 days of work.
- [ ] **AN6-5** — Secret-subkeys credential UX (eclipse-jkube). The build needs `secret-subkeys.asc` as a credential type; v0.3 secrets ship covers files generically. Surface a clearer `anvil secrets add --type gpg-subkey` flow that validates the file as a GPG keyring on add and exports the right path env-var (`GPG_KEYRING_PATH` or similar). Receipt-only if v0.3's generic file path already works after testing.
- [ ] **AN6-6** — Long-build harness cap (apache-hbase). Per-build configurable cap via `:anvil.dispatcher/build-timeout-min`. Default stays 30 min for sane defaults; document the override in `docs/dispatcher/long-builds.md`. Wild-corpus rerun config sets it to 90 min for hbase only.

## Anti-goals (resist)

- **Do not start v0.5 features in v0.4.** Remote cache is the obvious temptation; refuse it (AV4-6).
- **Do not abandon the AN6 series silently to chase leapfrog velocity.** The v0.3.3 receipt named those gaps publicly (AV4-1, AV4-7).
- **Do not host an AI service.** Anvil is self-host; AI authoring stays local-first (AV4-4).
- **Do not invent a new provenance format.** Adopt in-toto v1 + sigstore (AV4-5).
- **Do not break the page-load budgets.** p50 < 50 ms is a hard ceiling. Flaky dashboard + AI button + provenance pill must amortize together.
- **Do not refactor the bus / SSE convention while adding new event topics.** The TU1 design holds; add topics, don't reshape.
- **Do not ship a broken cache.** v0.5 territory; if T6 reveals demand pressure for caching, file it on the v0.5 board, don't compress it into v0.4.
- **Do not announce v0.4 leapfrog publicly until T7 ships the tag.** Soft-launch (gradient step 4) lands *before* tag per AV4-9, but the v0.4-specific feature story stays under wraps until the release page is live.
