# anvil v0.3.0 vs Jenkins LTS vs GitHub Actions

The seven Tier-1 parity features from the v0.3 board, scored against the two systems anvil exists to compete with.

✅ shipped at v0.3.0 · 🟡 partial / config-only at v0.3.0 · ⛔ not in scope

## Feature parity

| Feature | anvil v0.3.0 | Jenkins LTS | GitHub Actions |
|---|---|---|---|
| JUnit / surefire test dashboard | ✅ summary + failures + sortable table + 30-build sparkline (gated `:junit`) | ✅ via the JUnit plugin | ✅ Test Summary surface |
| Clickable file:line in logs | ✅ Problems tab; 6 YAML rules + GHA workflow-cmd parser | 🟡 Warnings NG plugin (separate install) | ✅ native problem-matchers |
| PR-check integration (GitHub) | ✅ webhook + Checks API + bus subscriber + build-page pill (PAT auth at v0.3.0; App in v0.3.1) | 🟡 GitHub Branch Source plugin | ✅ native |
| Declarative matrix builds | 🟡 parser + expander + grid view ship; child-build dispatcher in v0.3.1 | ✅ `matrix { axes { } }` | ✅ `strategy.matrix` |
| Scheduled triggers (cron) | ✅ Jenkins cron + H-spread + 7 aliases (Jenkinsfile DSL parse in v0.3.1; config-driven now) | ✅ `triggers { cron(…) }` | ✅ `on: schedule` |
| Secrets management | ✅ CLI + admin UI + AES-GCM + rotation + masking (Vault/KMS as v0.3.x plug-ins) | 🟡 Credentials plugin (separate install) | ✅ Repository / Org secrets |
| Tool-version pinning | ✅ mise + asdf auto-detect; pre-build provisioning | 🟡 Tool installers (per-tool plugin) | 🟡 `setup-*` actions per language |

## Architecture

| Dimension | anvil v0.3.0 | Jenkins LTS | GHA |
|---|---|---|---|
| Self-host | ✅ single uberjar; `lein run` or systemd recipe (`docs/deploy/`) | ✅ war + plugins ecosystem | ⛔ SaaS only (GHE runners self-hosted but controller is GitHub's) |
| Database | SQLite (single-node) | XStream-on-disk + plugins-do-their-own | n/a (cloud) |
| Plugin install | ✅ static — no runtime plugin loader; features compile in | ⚠ Update Center; restart often required; CVEs frequent | ✅ Marketplace actions; no controller restart |
| RBAC / multi-tenant | ⛔ single-team; trusted-IP gating only | 🟡 via Authorization Strategy plugin | ✅ org/repo permissions |
| Audit log | ⛔ v0.3.0 | 🟡 Audit Trail plugin | ✅ org audit log |

For RBAC / multi-tenant / audit / SSO / hosted, **Chengis** (the commercial tier) is the upgrade path. Anvil's stance is "single-team CI on a host you control."

## Migration cost

| Scenario | Effort |
|---|---|
| Existing Jenkinsfile, no plugins beyond core | Drop in. anvil parses + runs unchanged. |
| Jenkinsfile + Credentials plugin + JUnit plugin | Configure secrets via `anvil secrets add`; flip `:anvil.features/{junit,secrets}` on. ~10 min. |
| GHA workflow.yml | No drop-in translation. anvil reads Jenkinsfile, not workflow.yml. `anvil import` lands GHA translator in v0.4. |

## What anvil does NOT claim parity on at v0.3.0

- **GitHub App auth** — PAT works today; App protocol documented for v0.3.1.
- **Container-as-step** (`steps { container 'maven:…' { … } }`) — v0.4 leapfrog.
- **Flaky-test detection** (passed-on-retry analysis) — v0.4.
- **SLSA L3 provenance** — v0.4.
- **Remote build cache** — v0.5.
- **Plugin marketplace** — never. anvil's compile-in design is the security story; we don't want third-party code in our daemon.
- **The Jenkinsci/jenkins Jenkinsfile** — anvil can build it via a simplified pipeline today; the unmodified scripted-Pipeline matrix-via-`combinations()` ships in v0.4 alongside the Jenkins-self target.

## Bottom line

If your Jenkinsfile uses the day-to-day surface (declarative pipeline + sh + junit + parallel + withCredentials + matrix + cron), v0.3.0 is a drop-in upgrade. You get the 95× wall-clock advantage (TX8 receipt) and the 50-200× UI-load improvement immediately. The features Jenkins makes you install five plugins to get (PR checks, problem matchers, JUnit dashboard, secrets, tool versions) all ship in the same uberjar.

If you need RBAC, multi-tenant, or SOC2, that's Chengis territory — `chengis-core` is what powers anvil, and Chengis is what you upgrade to.
